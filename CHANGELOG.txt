# CHANGELOG

Unreleased:
  - rclone pinned to v1.75.1 by image digest.
  - Node plugin RBAC reduced to `get` on `rclone-secret` in the `csi-rclone` namespace. Delete the old ClusterRole and ClusterRoleBinding `csi-nodeplugin-rclone` after upgrading.
  - Breaking: dynamic provisioning fails unless StorageClass `pathPattern` contains `${.PVC.namespace}` as a whole path segment, or the StorageClass sets `sharedRemote: "true"`. StorageClass parameters are immutable, so existing StorageClasses have to be recreated.
  - Breaking: volumes are mounted read-only for `readOnly: true`, `ReadOnlyMany` and `ro` in `mountOptions`.
  - Expanded `pathPattern` values with `.` or `..` segments and non-octal `csi-rclone/umask` annotations are rejected.
  - Go 1.27, CSI spec 1.13 and client-go 0.37. The CSI requests are not logged.
  - One rclone mount per volume and node, staged in NodeStageVolume and bind-mounted into each pod. Its rc socket, config and VFS cache live in `/var/lib/csi-rclone` on the node.
  - rclone runs in a host systemd scope and survives node plugin restarts and upgrades. The node plugin needs `hostPID` and `/run/systemd`, see the node plugin manifest. New flags `--daemon-lifetime`, `--scope-memory-max` and `--scope-tasks-max`.
  - The node plugin remounts volumes whose rclone died and binds them into the pods again. Running containers need a restart to see the new mount.
  - Upgrading still loses all mounts once, because the previous release runs rclone inside its container. Drain nodes or restart the workloads.
  - rclone remote control runs on a unix socket instead of a localhost TCP port. Config files from `configData` are deleted on unmount.
  - Breaking: rclone backends and options are limited to an allow-list, see "rclone option allow-list" in the README. New flags `--allowed-backends`, `--allowed-endpoints` and `--unrestricted-rclone-options`.
  - Helm chart, published to `oci://ghcr.io/ruakij/charts/csi-rclone`. Images are published to `ghcr.io/ruakij/csi-rclone` for amd64 and arm64.
  - The controller validates requests and implements ValidateVolumeCapabilities.

3.1.0:
  - Rclone binary update to v1.74.3
  - Alpine base image update to 3.23

3.0.0:
  - Dropping support for kubernetes versions < 1.20 due to [external provisioner](https://github.com/kubernetes-csi/external-provisioner?tab=readme-ov-file#compatibility)+ compatibility requirement.
  - PersistentVolume provisioner support. Creation of PersistentVolume and using it in PersistentVolumeClaim via selector is still supported,
    no migration is required.
    If PersistentVolume was setting `remotePathSuffix`, it can be added to PVC annotations as `csi-rclone/storage-path` value now (namespace can be ommited if `pathPattern` includes it - `${.PVC.namespace}/${.PVC.annotations.csi-rclone/storage-path}`).
    If PersistentVolume was setting umask parameter, it's possible to set it in PVC annotations as `csi-rclone/umask` value now. 
  - cluster-driver-registrar is not required anymore since deployment resources declare CSIDriver object and registrar is [deprecated](https://kubernetes-csi.github.io/docs/cluster-driver-registrar.html#deprecated).

2.0.0:
  - rclone version v1.66.0
  - Custom rclone build (directory markers) removed since it's available in the official binary now
  - Separate cache paths for each mount process + cache removal on unmount
  - Remote control API endpoint for each mount process, this allows transfer state and vfs upload buffer queue monitoring
  - Delay rclone process shutdown until upload queue is empty (There's an additional timeout of 1 hour. That should be enough even for bigger files)
  - Graceful failover for plugin preStart

1.3.0: 
  - Container init changed to tini
  - rclone version v1.59.2
